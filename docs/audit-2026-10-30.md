## F1 — The quota panel is cycle-scoped but fed the analysis window (High)

**Claim:** "Requests this cycle" shows progress through the monthly allowance.

**Evidence:** `getUsageSummary(range)` passes the range total to
`buildQuotas`.

```sh
$ git checkout 6dc9bc6
$ node -e 'import("./apps/web/lib/data.ts").then(m => { for (const r of ["7d","30d","90d"]) { const q = m.getUsageSummary(r).quotas[0]; console.log(r.padEnd(4), q.used, "/", q.limit); } })'
7d   610465 / 2000000
30d  2502826 / 2000000
90d  7158253 / 2000000
```

The same account is 30% through its allowance at one setting and 358% over at
another. A billing-cycle quota cannot depend on how the chart is sliced.

**Cause:** analysis scope and billing scope modelled as one value.

**Fix:** `getBillingCycle()` owns the cycle, allowance, overage, and meters;
`getUsageSummary(range)` owns volume, error rate, and endpoints. The range
selector no longer touches a billing figure.

**Status:** fixed — `tests/e2e/dashboard.spec.ts` →
"the quota panel is cycle-scoped and ignores the chart window";
`tests/unit/data.test.ts` → "is independent of the analysis range".

## F2 — Spend charges the included volume, contradicting the price page (High)

**Claim:** the landing page says _"Metered at twelve dollars per million
requests beyond the included allowance."_

**Evidence:**

```sh
$ git checkout 6dc9bc6
$ node -e 'import("./apps/web/lib/data.ts").then(m => console.log(m.getUsageSummary("30d").costUsd.toFixed(2)))'
30.03
```

30.03 is `2,502,826 / 1e6 × $12` — the whole volume at the overage rate. The
Pro plan includes 2,000,000, so the correct figure is
`502,826 / 1e6 × $12 = $6.03`. The dashboard overstated the invoice five-fold
while the marketing copy described a different product.

**Cause:** `costUsd` computed per day as `requests / 1e6 × rate`, with no
reference to the plan.

**Fix:** overage is `max(0, requests − includedRequests)`; spend is
`overage / 1e6 × overagePerMillionUsd`, both read from `PLANS`.

**Status:** fixed — `tests/unit/data.test.ts` → "charges overage only, never
the included volume"; `tests/e2e/dashboard.spec.ts` → "cycle spend bills
overage only, not the included volume".

## F3 — The README's size claim is false (High)

**Claim:** "The dashboard is roughly 1,400 lines of TypeScript and CSS."

**Evidence:**

```sh
$ for f in $(git ls-tree -r 6dc9bc6 --name-only | grep -E '^apps/web/(app|components|lib)/.*\.(ts|tsx|css)$'); do git show 6dc9bc6:$f | wc -l; done | awk '{s+=$1} END {print s}'
3172
```

Off by more than a factor of two. A wrong number in the first screen of a
README costs more trust than the number ever earns.

**Cause:** written from memory, never measured.

**Fix:** state the measured split (1,807 TS + 1,524 CSS) and name the command
that produces it.

**Status:** fixed — `README.md`, "Stack".

## F4 — `formatCompact` rolls into an impossible unit (Medium)

**Claim:** a column of compact numbers stays aligned and readable.

**Evidence:**

```sh
$ git checkout 6dc9bc6
$ node -e 'import("./apps/web/lib/format.ts").then(m => console.log(m.formatCompact(999999), m.formatCompact(999999999)))'
1000K 1000M
```

Four significant digits where the contract is three, and a unit that reads as
a typo next to `1.00M` in the same column.

**Cause:** the unit is selected from the raw value, then the scaled value is
rounded up past the next threshold.

**Fix:** promote when the rounded value reaches 1000, then recompute precision.

**Status:** fixed — `tests/unit/format.test.ts` → "promotes into the next unit
instead of printing 1000K".

## F5 — `role="meter"` reports `aria-valuenow` above `aria-valuemax` (Medium)

**Claim:** the quota bar is a valid ARIA meter.

**Evidence:** at 125% the meter renders `aria-valuenow="2502826"` against
`aria-valuemax="2000000"`. An inverted range; assistive technology may
announce a percentage from an impossible scale. axe-core does not flag it,
which is why the existing accessibility suite missed it.

**Cause:** raw `used` passed straight through without clamping.

**Fix:** clamp `aria-valuenow` to the limit and carry the overage in
`aria-valuetext` ("2.50M of 2.00M, 125 percent, over limit").

**Status:** fixed — `tests/e2e/dashboard.spec.ts` → "the over-limit meter
reports a valid ARIA range".

## F6 — The quota limit is a duplicated literal (Medium)

**Claim:** the meter reflects the plan.

**Evidence:** `buildQuotas` hardcodes `limit: 2_000_000`, which is also
`PLANS.pro.includedRequests`. Change the pricing table and the meter silently
lies.

**Cause:** copy-paste instead of a lookup.

**Fix:** derive from `findPlan(CURRENT_PLAN_ID)`.

**Status:** fixed — `tests/unit/data.test.ts` → "takes the requests allowance
from the plan, not a literal".

## F7 — The seats meter contradicts the plan record (Medium)

**Claim:** the account is on Pro.

**Evidence:** `PLANS.pro.seats === 1`, but the panel rendered "Seats 3 of 5".
One of the two is wrong and nothing in the code notices.

**Cause:** the meter was decorative, not derived.

**Fix:** the third meter is usage, so it now reports webhook deliveries
(421,000 of 500,000). `"seats"` was removed from the `Quota` unit union, which
then had no producer.

**Status:** fixed — visible in `docs/dashboard.png`; covered by the quota
rendering tests.

## F8 — `sitemap.xml` ships a frozen `lastModified` (Medium)

**Claim:** the sitemap tells crawlers when the page last changed.

**Evidence:** `lastModified: "2026-10-30"` — a constant. Every future deploy
would claim that date.

**Cause:** a literal where a build-time value belonged.

**Fix:** emit `new Date()` at build time; the route is `force-static`, so it is
computed once per build.

**Status:** fixed — verified in the exported `apps/web/out/sitemap.xml`;
asserted by the SEO tests.

## F9 — `.env.example` advertises integrations that do not exist (Medium)

**Claim:** the file lists the variables the application reads.

**Evidence:**

```sh
$ git show 6dc9bc6:.env.example | grep -c '='
17
$ git grep -h 'process\.env\.' 6dc9bc6 -- apps packages tools | sed 's/.*process\.env\.\([A-Z_]*\).*/\1/' | sort -u
API_PORT
BASE_PATH
HOST
NEXT_PUBLIC_BASE_PATH
NEXT_PUBLIC_SITE_URL
PORT
```

Seventeen variables declared, three read by the application. The other
fourteen — a database URL, auth secrets, SMTP credentials, Stripe keys, a
Sentry DSN — are read by nothing.

**Cause:** scaffolding copied forward and never pruned.

**Fix:** keep the three the app reads, and say that adding an integration means
adding its variables in the same commit.

**Status:** fixed — `.env.example`.

## F12 — Revoked keys stay revealable and copyable (Low)

**Claim:** "Revoking takes effect on the next request."

**Evidence:** the Reveal and Copy buttons remain enabled on a revoked row. A
revoked secret is not usable; offering to copy it invites pasting a dead key
into production.

**Fix:** both actions are disabled when `status === "revoked"`, and revoking
hides a revealed secret.

**Status:** fixed — `tests/e2e/dashboard.spec.ts` → "a revoked key cannot be
revealed or copied".

## F13 — The copy-confirmation timer is never cleared (Low)

**Evidence:** `copyKey` schedules `window.setTimeout` with no handle kept. React
18 no longer warns, so the callback runs after unmount invisibly.

**Fix:** hold the timer in a ref, clear it on unmount and before rescheduling.

**Status:** fixed — `apps/web/app/dashboard/keys/page.tsx`.

## F14 — The chart keeps an out-of-range selection (Low)

**Evidence:** select day 90, switch to 7 days, and `activeIndex` stays 89.
`points[89]` is undefined, so the tooltip and crosshair vanish and the keyboard
position becomes undefined.

**Fix:** clamp the stored index against the current series length when
rendering.

**Status:** fixed — `apps/web/components/usage-chart.tsx`.

## F15 — `apps/api` is not consumed by anything (Low)

**Evidence:** nothing imports `@production/api`, and a static export cannot
call it at runtime.

**Decision:** retained deliberately as the backend skeleton and labelled as
such in the README. If the project stays static-only this is the first thing to
delete. Not a defect — recorded so the next reviewer does not re-litigate it.

**Status:** accepted, documented in `README.md` → "Known limitations".

## Not findings

Three things that look wrong and are not. Recorded so they are not "fixed" by
the next reviewer:

- **`position: relative` on the table scrollers.** Load-bearing. The header
  cells contain absolutely positioned visually-hidden labels; without a
  containing block they anchor to the page and extend its scroll width.
- **The fixed `REFERENCE_DATE`.** Deliberate. A moving "today" makes the
  prerendered HTML disagree with the client render on hydration.
- **No UI, CSS, or charting dependency.** Deliberate. The restraint is the
  design.
