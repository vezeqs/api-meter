## F16 — The accessible-name test cannot fail on the landing page (Medium)

**Claim:** "Every button has an accessible name" holds on all three routes.

**Evidence:**

```sh
$ cd apps/web/out
$ grep -o "<button" index.html | wc -l
0
$ grep -o "<button" dashboard/index.html | wc -l
7
```

The assertion enumerates `document.querySelectorAll("button")` and asserts the
count of unnamed ones is zero. On `/api-meter/` that set is empty, so the test
asserts `0 === 0`. It passes for the same reason an empty file passes a spell
check.

**Cause:** the check was written for the dashboard and applied to every route
without confirming the landing page had anything to check.

**Fix:** check every interactive element (`button`, `a[href]`, `input`,
`select`, `textarea`) and require a minimum count, so a page with no controls
fails rather than passes.

**Status:** fixed — `tests/e2e/audit.spec.ts` → "every interactive element has
an accessible name". Verified by making React render an unnamed link; the test
reports `<a class="…secondary" href="/api-meter/dashboard/keys/"></a>`.

A note for the next auditor: injecting the element into the built HTML does
**not** reproduce this. React hydration removes nodes it did not render, so the
injection is gone before the assertion runs. The source has to be changed.

## F17 — Key creation is announced once and then silently (Low)

**Claim:** the keys screen announces a newly created key to assistive
technology.

**Evidence:**

```sh
$ sed -n '257,259p' apps/web/app/dashboard/keys/page.tsx
      <p className="visually-hidden" aria-live="polite">
        {createdId ? "New key created and revealed." : ""}
      </p>
```

The text does not depend on which key was created. Creating a second key
re-renders the same string, the DOM text does not change, and an `aria-live`
region only announces changes. The first creation is announced; every one after
it is silent.

**Cause:** a constant message behind a state flag.

**Fix:** include the key name, so each creation produces different text.

**Status:** fixed — `tests/e2e/dashboard.spec.ts` → "each created key is
announced with its own name".

## F18 — The tools hardcode the deployment URL (Low)

**Claim:** the Open Graph card and the captures show the real deployment.

**Evidence:**

```sh
$ grep -n "vezeqs.github.io\|127.0.0.1:4321" tools/*.mjs
tools/capture.mjs:19:const BASE = "http://127.0.0.1:4321/api-meter";
tools/og.mjs:110:      <span>vezeqs.github.io/api-meter</span>
```

`apps/web/lib/site.ts` is the single source for the origin and subpath. Both
tools bypass it. Renaming the repository or setting `NEXT_PUBLIC_SITE_URL`
leaves the card advertising a URL the site no longer uses — the same
duplication that produced the `/api-meter/meter` bug in the first pass.

**Cause:** literals copied at authoring time.

**Fix:** the deployment host no longer appears in either tool. `og.mjs` reads
`SITE_URL` and `BASE_PATH` from the shared `site-config.mjs`; `capture.mjs`
derives its base path from the same module. The `127.0.0.1` origin in
`capture.mjs` is intentional: it is the loopback address of the local preview
server, not a deployment address. It can be overridden with `CONNECT_HOST`;
the server's bind address is `HOST`.

**Status:** fixed — `tests/unit/tools.test.ts` → "does not hardcode the
deployment host" and "does not import TypeScript".

## F19 — The static server prints a doubled slash (Low)

**Claim:** `pnpm preview` prints the address to open.

**Evidence:**

```sh
$ node tools/serve-export.mjs &
serving /home/larpsahur/Projects/production/apps/web/out/ at http://127.0.0.1:4321/api-meter//
```

A copy-pasted address with `//` resolves in most browsers but is not what the
server serves, and it is the first thing a new contributor sees.

**Cause:** `${PREFIX}/${sep}`, where `sep` is already `/`.

**Fix:** drop the redundant separator.

**Status:** fixed — `tests/unit/tools.test.ts` → "the preview server prints a
clean URL".

## F20 — `SECURITY.md` carries two claims it cannot back (Medium)

**Claim:** a response-time commitment, and that the project is pre-release.

**Evidence:**

```sh
$ grep -n "72 hours\|pre-release" SECURITY.md
14:Expect an acknowledgement within 72 hours. Once a fix is ready, it ships with a
19:This project is pre-release. Only the latest commit on `main` is supported.
$ git tag -l
v1.0.0
v1.0.1
```

This is a demonstration repository with one maintainer and no on-call. A
72-hour commitment is a promise nobody is positioned to keep, and a security
policy is exactly the document where an unkeepable promise is worst. The second
line is simply out of date: the project has been tagged twice.

**Cause:** boilerplate adopted without being sized to the project, then not
revisited at release.

**Fix:** state the actual arrangement — best effort, no guaranteed window — and
describe support in terms of releases rather than calling a released project
pre-release.

**Status:** fixed — prose; not testable, and saying so is better than inventing
an assertion for it.

## F21 — The README hardcodes test counts that already drifted (Medium)

**Claim:** "| Unit (`node:test`) | 32 |" and "| End-to-end (Playwright) | 43 |".

**Evidence:**

```sh
$ git log -p --format='%h %s' -2 -- README.md | grep -E "^[0-9a-f]{7} |Unit \("
40e2d60 Fix the billing model and ship 1.0.0
+| Unit (`node:test`)      | 16    | ...
4be41ea Harden the audit and the proof
-| Unit (`node:test`)      | 16    | ...
+| Unit (`node:test`)      | 32    | ...
```

The number changed by a factor of two in the commit immediately after it was
introduced. Nothing verifies it, so it will drift again the next time a test is
added — including in this commit, which adds more.

**Cause:** a live document carrying a figure that only a test run can produce.

**Fix:** the README describes what each suite proves and gives the command that
prints the count. The exact figures live in the dated `CHANGELOG.md`, where a
snapshot is correct because it is attached to a release.

**Status:** fixed — `README.md`, `CHANGELOG.md`.

## Not findings

Checked and dismissed, recorded so the next pass does not re-open them:

- **Endpoint sort has no tie-break for duplicate paths.** `/v1/events` exists as
  both GET and POST. Sorting by path left their relative order to the stable
  sort; in the current data that already happened to be alphabetical by method,
  so no wrong result was observable. Marked **suspected, not reproducible** at
  the time. **Superseded:** the comparator now always falls back to path then
  method, so the order no longer depends on the input, and a test asserts it.
- **`markLast` renders as an ellipse.** The sparkline uses
  `preserveAspectRatio="none"`, so a circle stretches. At 1440px the distortion
  was sub-pixel and I called it not a bug. At 390px the sparkline column is
  roughly half as wide, the horizontal scale halves, and the dot becomes a
  visible ellipse. **Superseded:** the prop is gone; only the line is drawn.
- **`ratio()` returns 1 when the previous period is zero.** Unreachable with
  the seeded history — every prior period has traffic. **Superseded:** it now
  returns `NaN`, which renders as a dash rather than a fabricated `+100%`, and
  `formatDelta` has a test for the non-finite case.
- **`QuotaUnit` is exported but only used inside `packages/shared`.** Harmless;
  it is the type of a public field.
- **`apps/api` is unconsumed.** Carried over from the first pass as an accepted
  decision.
