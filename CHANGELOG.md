# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.1] - 2026-10-30

Documentation and test hardening. No change to the product.

### Added

- Asset integrity tests. Every image the README references must exist, be
  non-empty, and match its expected dimensions; the demo GIF must loop and stay
  under two megabytes. Screenshots are generated, so something has to fail when
  they rot.
- A reproduction command and observed output for each audit finding.

### Changed

- The audit moved to `docs/audit-2026-10-30.md`, in the same `docs/` directory
  as the images it refers to, and every finding now carries a claim, evidence,
  cause, fix, and status.
- `AGENTS.md` is organised around invariants and sharp edges rather than
  general advice.
- README figures re-measured against the tree and paired with the command that
  produces them.

## [1.0.0] - 2026-10-30

First tagged release. The dashboard is complete, audited, and deployed.

### Added

- Landing page with the product's pricing, a live quota specimen, and
  `SoftwareApplication` structured data.
- Dashboard overview: request volume chart with keyboard navigation, quota
  meters, and a sortable, filterable endpoint table with sparklines.
- API keys screen: reveal, copy, revoke with confirmation, and create.
- Billing cycle model, separate from the analysis window. `getBillingCycle()`
  owns the allowance, overage, spend, and quota meters; `getUsageSummary()`
  owns volume, error rate, and endpoints.
- Deterministic data layer with a fixed seed and fixed reference date, so the
  prerendered HTML and the client render always agree.
- Unit test suite on `node:test` for formatting, billing arithmetic, and asset
  integrity.
- Playwright suite covering layout, console health, document structure,
  base-path correctness, SEO output, axe-core under WCAG 2.1 AA in both
  themes, and the behaviour of every control.
- Static export configured for GitHub Pages, with the base path derived from
  the repository at deploy time.
- `sitemap.xml` and `robots.txt` generated at build time; the dashboard is
  excluded from the index.
- Open Graph card generated from the same design tokens as the site.
- Screenshots and a demo GIF for the README, regenerated by `pnpm capture`.
- Deploy workflow publishing the export to GitHub Pages.
- `CODE_REVIEW.md`, recording the audit of the previous revision.

### Changed

- Spend is overage-only, derived from the plan. The plan fee is billed
  separately and is not usage.
- Quota limits come from `PLANS` instead of a duplicated literal.
- The third quota meter reports webhook deliveries rather than seats, which
  contradicted the plan record.
- `sitemap.xml` `lastmod` is the build date rather than a frozen constant.
- README figures are measured and pinned to the commands that produce them.

### Fixed

- The quota panel was fed the analysis window, so the same account read 30% of
  its allowance at seven days and 358% at ninety.
- Spend charged the full volume at the overage rate, overstating the invoice
  five-fold.
- `formatCompact` produced `1000K` and `1000M` instead of promoting units.
- The over-limit meter reported `aria-valuenow` above `aria-valuemax`, an
  invalid ARIA range.
- Endpoint totals were multiplied by the number of days in the period, so the
  table summed to roughly thirty times the headline figure.
- The base path defaulted to empty in `next.config.ts` while links assumed
  `/api-meter`, breaking every internal link in the export.
- A visually-hidden table header anchored to the page instead of its scroll
  container, giving every table page a horizontal scrollbar.
- `--ink-3` sat at 3.2:1 against the page, below the 4.5:1 minimum.
- Revoked API keys could still be revealed and copied.
- The chart kept an out-of-range selection when the reporting window shrank.

### Removed

- Fourteen environment variables that nothing read, including a database URL,
  SMTP credentials, Stripe keys, and a Sentry DSN.
- The `test` task in `turbo.json`, which no workspace package implemented.
- A no-op self-assignment in the key revocation path.

## [0.1.0] - 2026-10-30

### Added

- pnpm workspace with a Turborepo task pipeline.
- `apps/web`: Next.js 16 app with the App Router and React 19.
- `apps/api`: Fastify 5 service with a `/health` endpoint.
- `packages/shared`: shared types, plans, and the health contract.
- Strict TypeScript, ESLint, and Prettier configuration.
- CI workflow running format, lint, typecheck, build, and an API smoke test.
- Issue templates, pull request template, and Dependabot configuration.
- MIT license, security policy, contribution guide, and code of conduct.
